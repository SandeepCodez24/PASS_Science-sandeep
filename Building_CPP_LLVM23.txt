===============================================================================
 BUILDING nc.exe (C++ back end) - LLVM 23.1.0 EDITION
 Toolchain: in-house LLVM 23.1.0 (clang++ / lld-link / llvm-ar / ninja)
 No MSVC compiler, no gcc.  Applies to BOTH repositories:
     Astra_development  (toolchain per TOOLCHAIN_DEVELOPMENT.txt)
     Astra_Release      (toolchain per TOOLCHAIN_RELEASE.txt)
 Replaces the LLVM 21 version of Building_CPP.txt.
===============================================================================

In the steps below, <REPO> means the full path of the repository folder, e.g.
    D:\My Research Works\PASS Science Works\Main_Repository\Astra_development

What changed compared with the LLVM 21 guide
  * Toolchain is LLVM 23.1.0. Expected version strings updated.
  * Eigen upgraded to 5.0.1 and moved OUT of the toolchain folder into
    <REPO>\build\third_party\eigen
    (Eigen 3.4 used to live in build\toolchain\custom_libs\eigen3). See section 2.
  * New CMake options for development vs release builds (section 6).
  * libomp.dll (and the ASan DLL when used) is copied next to nc.exe
    automatically after every build.
  * The first build after the migration MUST start from a clean
    build\nc-build (the cache still points at the LLVM 21 compilers).
  * New section 9: toolchain self-tests, with -no-canonical-prefixes.


-------------------------------------------------------------------------------
 0. WHY "cmake --build build/nc-build" CANNOT RUN STRAIGHT AWAY
-------------------------------------------------------------------------------
build\nc-build\CMakeCache.txt stores ABSOLUTE paths: the source folder, the
toolchain folder and the compiler paths. After a copy, a rename, OR A
TOOLCHAIN CHANGE (such as LLVM 21 -> 23) CMake either stops with
    "The current CMakeCache.txt directory ... is different ..."
or silently keeps using the old compilers. So:
    -> delete build\nc-build
    -> configure once  (cmake -S ... -B ...)
    -> after that, "cmake --build build/nc-build" works as usual.

 1. ONE-TIME CHECKS (once per machine)
-------------------------------------------------------------------------------
  - Visual Studio 2022 Build Tools (C++ workload + Windows SDK).
    Provides the C++ standard library headers, Windows SDK libraries and
    rc.exe. The MSVC compiler (cl.exe) itself is NOT used.

 2. MAKE SURE THE REPOSITORY HAS EVERYTHING
-------------------------------------------------------------------------------
  a) The toolchain (LLVM 23.1.0):
        <REPO>\build\toolchain\bin\clang++.exe
        <REPO>\build\toolchain\lib\clang\23\include\...
     Contents exactly as in TOOLCHAIN_DEVELOPMENT.txt (development repo) or
     TOOLCHAIN_RELEASE.txt (release repo). No LLVM 21 files anywhere.

  b) The CMake toolchain file (LLVM 23 version):
        <REPO>\cmake\clang-windows.cmake
     It stops with a clear error if the toolchain is not LLVM 23, and contains
     -no-canonical-prefixes (see section 8, "lld-link: permission denied").

  c) Eigen 5.0.1 (header-only matrix library):
        <REPO>\build\third_party\eigen\Eigen\Dense     (and the rest of Eigen\)
        <REPO>\build\third_party\eigen\LICENSE         licence files - keep
        <REPO>\build\third_party\eigen\COPYING.*       all of them (see 2e)
        <REPO>\build\third_party\eigen\VERSION.txt     "Eigen 5.0.1, from
                                                       gitlab.com/libeigen/eigen"
     eigen is the folder that CONTAINS Eigen\. If the download unpacked as
     eigen\eigen-5.0.1\Eigen\..., move the contents up one level.
     src\main\cpp\CMakeLists.txt finds it there automatically (another place:
     -DNC_EIGEN_DIR=<folder>).
     Version check (Eigen 5 keeps its version in Eigen\Version):
        Select-String -Path build\third_party\eigen\Eigen\Version -Pattern "EIGEN_VERSION_STRING"
        -> #define EIGEN_VERSION_STRING "5.0.1"
     One-time check that no other CMake file still uses the old location
     (no output = fine):
        Get-ChildItem src\main\cpp, cmake -Recurse -Include CMakeLists.txt,*.cmake | Select-String "custom_libs"

  d) The C++ sources:
        <REPO>\src\main\cpp\CMakeLists.txt

  e) Eigen licence files (from the root of the eigen-5.0.1 download):
        LICENSE, COPYING.MPL2, COPYING.APACHE, COPYING.BSD, COPYING.MINPACK,
        COPYING.README
     Eigen is MPL2; a few files carry Apache-2.0 or BSD code (for example
     Eigen\src\Core\arch\Default\BFloat16.h is Apache-2.0), so ship ALL of
     them with Astra, e.g. in <install>\licenses\Eigen\.

  Do NOT copy build\nc-build from anywhere. It is deleted in step 4.

  CAUTION: the toolchain lives inside build\. Never delete the whole build\
  folder - only build\nc-build (and build\nc-build-debug).


-------------------------------------------------------------------------------
 3. SET UP THE TERMINAL  (needed in EVERY new PowerShell window)
-------------------------------------------------------------------------------
Nothing below persists after the window is closed. Run in this order:

  # 3.1 Enter the VS developer shell (STL headers, SDK libs, rc.exe).
  #     It changes the current folder, so cd comes AFTER it.
  & "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\Tools\Launch-VsDevShell.ps1" -Arch amd64 -HostArch amd64

  # 3.2 Go to the repo root
  cd "<REPO>"

  # 3.3 Point at the toolchain and put it first on PATH
  $env:NC_TOOLCHAIN_ROOT = "$PWD\build\toolchain"
  $env:PATH = "$env:NC_TOOLCHAIN_ROOT\bin;$env:PATH"

  # 3.4 Quick checks
  Test-Path "$env:NC_TOOLCHAIN_ROOT\bin\clang++.exe"     # True
  clang++ --version                                      # clang version 23.1.0
                                                         # Target: x86_64-pc-windows-msvc
  Test-Path "$PWD\build\third_party\eigen\Eigen\Dense"   # True
  Get-Command rc.exe | Select-Object Source              # ...\Windows Kits\10\bin\...\rc.exe

  Select-String -Path build\third_party\eigen\Eigen\Version -Pattern "EIGEN_VERSION_STRING"   # "5.0.1"


-------------------------------------------------------------------------------
 4. FIRST BUILD  (configure + build)  - REQUIRED once after the LLVM 23 switch
-------------------------------------------------------------------------------
  # 4.1 Remove the old build cache (safe if it does not exist)
  Remove-Item -Recurse -Force build\nc-build -ErrorAction SilentlyContinue

  # 4.2 Configure - keep it on ONE line
  cmake -S src/main/cpp -B build/nc-build -G Ninja --toolchain "$PWD\cmake\clang-windows.cmake" -DCMAKE_BUILD_TYPE=Release

      Expected:  -- The CXX compiler identification is Clang 23.1.0 with GNU-like command-line
                 -- nc Eigen           : vendored (...build/third_party/eigen)
                 -- nc OpenMP          : ON
      If it says 21.1.6: build\nc-build was not deleted, or NC_TOOLCHAIN_ROOT
      points at an old toolchain.
      If it says MSVC: -G Ninja or --toolchain is missing.

  # 4.3 Build
  cmake --build build/nc-build

  # 4.4 Result: nc.exe is written to  <REPO>\src\main\cpp\nc.exe
  #     together with libomp.dll (copied automatically; nc.exe needs it).
  #     Quick test:
  & ".\src\main\cpp\nc.exe"        # should show the ">> " prompt


-------------------------------------------------------------------------------
 5. LATER BUILDS IN THE SAME FOLDER
-------------------------------------------------------------------------------
  - Open a terminal and do step 3.
  - Then just:
        cmake --build build/nc-build
  - Repeat step 4 (delete build\nc-build + configure) ONLY when:
        * the repo folder is moved, copied or renamed,
        * the toolchain folder or LLVM version changes,
        * clang-windows.cmake or the build type (Release/Debug) changes,
        * a new .cpp file is not picked up / CMakeLists.txt changed a lot.


-------------------------------------------------------------------------------
 6. BUILD PROFILES  (development repo vs release repo)
-------------------------------------------------------------------------------
 Use a separate build folder per profile so their caches never mix.
 NOTE: every profile writes nc.exe to src\main\cpp\, so the last build wins.

 DEVELOPMENT REPO
  Debug (assertions + Eigen bounds checks on, no optimisation):
    cmake -S src/main/cpp -B build/nc-build-debug -G Ninja --toolchain "$PWD\cmake\clang-windows.cmake" -DCMAKE_BUILD_TYPE=Debug
    cmake --build build/nc-build-debug

  Release (fast, for testing performance):
    cmake -S src/main/cpp -B build/nc-build -G Ninja --toolchain "$PWD\cmake\clang-windows.cmake" -DCMAKE_BUILD_TYPE=Release
    cmake --build build/nc-build

  Memory-bug hunting (AddressSanitizer + UndefinedBehaviorSanitizer):
    cmake -S src/main/cpp -B build/nc-build-asan -G Ninja --toolchain "$PWD\cmake\clang-windows.cmake" -DCMAKE_BUILD_TYPE=Release -DNC_SANITIZE="address;undefined"
    cmake --build build/nc-build-asan
    (must be Release; debug symbols are added automatically. The ASan DLL is
     copied next to nc.exe. Put build\toolchain\bin on PATH - step 3.3 does
     this - so crash reports show file and line.)

 RELEASE REPO  (the nc.exe that ships to users)
    cmake -S src/main/cpp -B build/nc-build -G Ninja --toolchain "$PWD\cmake\clang-windows.cmake" -DCMAKE_BUILD_TYPE=Release -DNC_LTO=ON
    cmake --build build/nc-build
    Then check what nc.exe depends on:
    build\toolchain\bin\llvm-readobj.exe --coff-imports src\main\cpp\nc.exe | Select-String "Name:"
    Expected: only Windows system DLLs (KERNEL32.dll ...) and libomp.dll.
    Ship nc.exe + libomp.dll. Archive nc.pdb with the release; never ship it.

 What Release sets automatically (see the option list at the top of
 src\main\cpp\CMakeLists.txt):
    -O2 -DNDEBUG            full speed; assert() and Eigen checks off
    static C runtime        nc.exe needs no Visual C++ runtime on user PCs
    -fopenmp                multithreading; Eigen products use all cores
    -march=x86-64-v2        runs on practically every 64-bit PC
    nc.pdb                  debug symbols for crash analysis
    -DNC_LTO=ON adds ThinLTO (slower link, faster nc.exe) - release repo.
 Every option can be overridden, e.g. -DNC_CPU_BASELINE=x86-64-v3 (AVX2).

-------------------------------------------------------------------------------
 Symptom                                   Cause / fix
 ----------------------------------------  ------------------------------------
 "Building for: Visual Studio 17 2022" /   Generator not given. Delete
 compiler identification is MSVC           build\nc-build, configure with
                                           -G Ninja --toolchain ...

 Compiler identification is Clang 21.1.6   Old cache or old toolchain. Delete
                                           build\nc-build; check that
                                           NC_TOOLCHAIN_ROOT is this repo's
                                           build\toolchain.

 "Eigen not found" (configure) or         Eigen is not at
 'Eigen/Dense' file not found              build\third_party\eigen\Eigen\Dense
                                           (check for an extra eigen-5.0.1
                                           folder level). See section 2c.

 Configure still shows .../eigen3 after    Old cache. Delete build\nc-build
 renaming the folder                       (and the other build folders) and
                                           configure again.

 "Resource directory not found ...         The toolchain folder is not LLVM 23
 lib/clang/23/include"                     (old 21 files) or lib\clang\23 is
                                           missing. Re-copy per the
                                           TOOLCHAIN_*.txt checklist.

 #error ... MPL2 ... (from an Eigen        Should not happen with Eigen 5 (all
 header)                                   LGPL code removed). Check that the
                                           folder really is 5.0.1 (section 2c).

 "NC_SANITIZE=address needs                Sanitizer builds must use
 -DCMAKE_BUILD_TYPE=Release"               -DCMAKE_BUILD_TYPE=Release.

 nc.exe: "libomp.dll was not found"        Build again (it is copied after each
                                           build), or copy
                                           build\toolchain\bin\libomp.dll next
                                           to nc.exe. The installer must ship it.

 Huge number of Eigen warnings             The old include path is still used
                                           (not SYSTEM). Use the new
                                           CMakeLists.txt.

 'clang++' is not recognized               NC_TOOLCHAIN_ROOT wrong. It must be
                                           the folder that CONTAINS bin\.

 Could not find toolchain file             cmake\clang-windows.cmake missing or
 "cmake/clang-windows.cmake"               relative path used. Always pass
                                           "$PWD\cmake\clang-windows.cmake".

 CMake was unable to find a build          Knock-on error of a failed configure.
 program corresponding to "Ninja"          Fix the first error, delete
                                           build\nc-build, configure again.

 No CMAKE_RC_COMPILER could be found       Not in the VS developer shell (3.1).
 'iostream' file not found /               Same - run step 3.1 first.
 cannot open kernel32.lib

 lld-link: permission denied               clang resolved the D: alias to
                                           C:\D-Drive\D\... and Windows refuses
                                           to start programs via that path.
                                           Fixed by -no-canonical-prefixes:
                                           already in clang-windows.cmake; add
                                           it by hand to any direct clang++
                                           command (section 9).

 no such file or directory: 'Research'     A path with spaces was put into a
                                           flag. Do not add paths to the
                                           *_LINKER_FLAGS in the toolchain file.

 "CMakeCache.txt directory is different"   build\nc-build was copied from
                                           another folder. Delete it, configure.

 Lines joined with backticks (`) fail      A multi-line command was pasted as
 strangely                                 one line. Use one-line commands.

 warning: -Wmicrosoft-include (value.h)    Harmless on Windows; backend team
                                           should fix the include path in
                                           compiler/compiler_src/parser/parser.h.

 9. TOOLCHAIN SELF-TESTS  (run after setting up a toolchain; from <REPO>\build)
-------------------------------------------------------------------------------
 Files: test_omp.cpp, test_asan.cpp. Run each line separately.
 -no-canonical-prefixes stops clang from swapping D:\ for C:\D-Drive\D\.

 OpenMP (both repos):
   toolchain\bin\clang++.exe -no-canonical-prefixes -O2 -fopenmp -fuse-ld=lld test_omp.cpp -o test_omp.exe
   Copy-Item toolchain\bin\libomp.dll .
   .\test_omp.exe
   PASS: thread count = your logical cores, sum = 200000000

 AddressSanitizer (development repo only):
   $env:PATH = "$PWD\toolchain\bin;$env:PATH"
   toolchain\bin\clang++.exe -no-canonical-prefixes -g -fsanitize=address -fuse-ld=lld test_asan.cpp -o test_asan.exe
   Copy-Item toolchain\lib\clang\23\lib\windows\clang_rt.asan_dynamic-x86_64.dll .
   .\test_asan.exe
   PASS: stops with "ERROR: AddressSanitizer: heap-buffer-overflow"

 Afterwards delete the test .cpp/.exe/.pdb/.obj and copied .dll files.
